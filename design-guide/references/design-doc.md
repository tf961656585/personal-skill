# 落地设计文档（design-doc）生命周期

适用范围：可逆决策（UI、交互、流程、体验、模块内部结构），但用户明确要求"先出设计文档"时。该形态不归 spec 系（不进 spec 状态机、不属 spec-guide 管理），也不归原型路径（不产出可运行物）。

## 1. 文件与字段

- 路径：`docs/<域>/<主题>-design.md`；不符合 `-design.md` 后缀报提示级。
- 首部 frontmatter：`type: design-doc`、`status`（五态）、可选 `spec`（关联的 spec/ADR 路径）。
- 字段与枚举的唯一源是 spec-guide `references/frontmatter.md` 第四节；本文件只定义状态转移的语义与时机。正文状态行可保留给人看，口径以 frontmatter 为准；冲突由 `design_lint.py` 报阻断级。

## 2. 状态机

`草稿 → 待评审 → 已评审 → 已实现 → 已收口`

| 状态 | 含义 | 强制推进点 |
|---|---|---|
| 草稿 | 文档在写，未提交评审 | 完成初稿 |
| 待评审 | 已提交用户评审，等待明确结论 | 用户确认进入实现 |
| 已评审 | 评审通过，实现授权已给 | 实现落地并验证通过，且契约/边界/状态所有权决策已回写 spec/ADR |
| 已实现 | 实现完成，决策已回写 | 文档与验收原型不再作为对照材料存续（原型退役删除、文档不再维护） |
| 已收口 | 生命周期终点，文档保留为决策记录 | —— |

状态推进是评审/实现的强制伴随动作，不得只停留在对话里不落文档。

## 3. 强制触发点与回写

- 评审通过：推进为「已评审」。评审中拍板的契约/边界/状态所有权决策必须回写 spec/ADR（spec-guide 场景 C）；纯交互细节不回写。
- 实现落地并验证通过：推进为「已实现」。涉及不可逆决策的内容必须已由 spec 承载；设计文档只承载可逆细节。
- 原型退役 + 文档不再维护：推进为「已收口」。文档保留为决策记录，不删除。
- 回写未完成前不得推进到「已实现」；不得用「已收口」掩盖未回写的决策。

## 4. 与登记表、原型的关系

- design-doc 有 frontmatter，不登记进 `docs/design-registry.yaml`；登记表只承载流程图与原型。
- 设计文档配套的验收原型按原型路径管理：验收通过 → 回写 → 退役删除；原型退役前，其涉及不可逆决策的部分必须已回写 spec/ADR。
- 设计文档本身不产出可运行物；需要可运行验收时，另走原型路径。
