# 设计评审类子代理的协调协议

适用范围："设计专家评审 + 实现子代理修复"的多轮验收场景。以下为游戏项目实测，其他项目按等价物替换；不在该场景时不要加载本文件。

- **评审简报预装四件**：① 含坐标表 / 设计决策的 README 类文档路径；② 原型与实现双侧全图，且截图文件名与内容必须经主代理核验（错图会让专家基于错误证据下结论）；③ 测试数据覆盖矩阵——明确哪些设计主张当前数据下不可验（否则"数据缺失"会被误报为"未实现"）；④ 相关视图脚本清单。spec、prefab YAML 不必预装（设计评审不消费）。
- **多轮验收逐 ID 对账**：初审按区域编号（如 1.1–6.5），复盘 / 终审沿用同一组 ID 标 ✅/⚠️/❌/🆕；主代理转述实现任务时按 ID 引用，三轮往返零混乱。
- **图证规则**：设计主张没有真实截图佐证一律判"未验证"，不接受代码审读或实现者文字报告代替；"合规但不够味"的呈现差距记入后续阶段欠账清单，不阻断当阶段验收。截图是材料：agent 侧只核可程序化项，"够不够味"与整体观感归用户判定（visual-handoff）。
- **修复 + 全态截图验证的大任务拆开委派**：验证循环（改值 → 截图 → 放大 → 再看）是耗时大头（实测约三成），实现者应先搭好 dev 调试菜单（数据注入 / 状态直达 / 截图）再动工，或修复与验证分轮委派。
