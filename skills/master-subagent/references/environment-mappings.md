# 环境能力映射（按需追加）

SKILL.md 正文只写能力与降级路径。本节记录具体环境中这些能力的注册名；新增环境时只追加条目，不改正文。

## DSH harness（0.2.2-rc.1，desktop profile）

| 能力 | 注册名 / 机制 | 备注 |
|---|---|---|
| 可续委派 | `subagent` / `subagent_fork` | 立即返回子代理 id，不返回结果；结算时运行时发完成通知，之后可 `send_message` 续跑 |
| 一次性委派（同步） | `delegate_sync`（由 sync-delegate 插件提供） | 阻塞到结果或超时；超时不杀子代理，结果以跟进消息送达。**插件未安装时降级为：结束本轮、等完成通知**，不得用轮询模拟等待 |
| 续跑 | `send_message`（仅直接子级） | 子代理各状态均可作为续跑对象；正在工作的目标在最近步骤接收 |
| 中断 | `interrupt_agent` | 只停当前轮、立即返回、不带回部分产出；子代理仍可续跑，但不会自动把结果送回来 |
| 后代查询 | `list_agents`（children / descendants） | 只返回 `running` / `inactive` 与标签，**不带耗时、步数、进度**；不能用来判断「是否卡死」 |
| 完成通知 | 子代理结算后自动通知父代理；父代理空闲时起新一轮 | 与工具结果分离；繁忙父代理在下一步收到 |

来源：一次性同步委派的两条路径（正常返回、超时后跟进送达）已实测；其余条目来自本机会话日志与随包文档。

已知坑：`interrupt_agent` 在没有外部时限依据时不该用——打断后子级停在原地，结果不会自动回来。异步委派路径本身不提供耗时（`list_agents` 不带时间），所以「我觉得它跑了很久」不能作为依据；需要确定的等待就改用一次性同步委派，由它的超时计时给出真实经过时间。
