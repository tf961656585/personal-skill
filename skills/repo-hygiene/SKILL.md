# Repo Hygiene — 仓库级周期卫生巡检

## 定位

多 agent 协作下，每个任务都会在仓库留下副产物（plan、临时脚本、ignore 条目、守卫、配置）。任务级收尾由 sweep 负责，但**跨任务累积的存量失序没有任何任务会认领**——它需要一个独立的周期巡检机制。本 skill 之于仓库，相当于 reflect 之于 memory/。

与相近 skill 的边界：

- **sweep**：任务级，扫本轮编辑/新建的产物，用户显式调用。
- **reflect**：memory/ 记忆库的沉淀与巡检。
- **repo-hygiene**：仓库级，扫跨任务累积的存量失序，周期调用。
- **implementation-discipline / 门禁脚本**：代码层质量，本 skill 不重复。

## 防的两类失效（why）

1. **机制建立 ≠ 机制运行**：ignore 条目加了但已追踪文件没清、校验脚本写了但没接进 pipeline、索引建了但登记率不足。这类失效没有任何报错会暴露它——机制安静地不工作，还制造"已治理"的假象。
2. **产物只有创建、没有生命周期**：过程产物（plan/临时稿）、一次性脚本、迁移遗留、客户端目录壳，只进不出必然无限堆积，并被后续 agent 误当事实来源（幽灵文件上的补丁循环）。

## 触发

- 手动：用户调用 `/repo-hygiene`，或表达"巡检仓库 / 仓库卫生 / 仓库是不是又乱了"。
- 建议节奏：每 1-2 周一次；大规模重构/迁移完成后必跑一次（迁移遗留是最高发的失序来源）。
- v1 不做自动触发，避免无人确认下产生清理动作。

## 核心原则

1. **脚本给信号，人来裁决**。巡检脚本（`scripts/repo-hygiene.py`）只做机械检测与统计，输出疑似清单；每个信号是否成立、如何处置，由 agent 按「判定与处置」核实后给建议，用户确认才动手。机械信号有误报（启发式检测），禁止按脚本输出直接删除。
2. **报告分级，不一锅端**。处置建议分两档：可安全清理（证据充分、无引用）、需人工裁决（归属不明 / 可能有历史价值）。
3. **巡检自身不留产物**。巡检结果只在对话中报告，不落盘成新文档——否则巡检本身就在制造它要防的过程产物。需要留档时由用户决定去向（issue / memory）。
4. **不扩大为重构**。巡检发现的是失序信号，不是架构判断；命中架构问题（契约漂移、双线实现）时转 problem-triage / design-review，不在本 skill 内展开。

## 脚本知识的三个层级（防"脚本追着仓库跑"）

机械脚本用封闭枚举匹配开放世界的仓库，必然持续过期——这是结构性张力，无法消除，只能分层管理：

1. **核心稳定层**：git 反向漏、化石/重复条目、悬空引用——git/JSON 的普世语义，几乎不随生态变化，维护频率极低。
2. **枚举与测量层**：剪枝表、默认过程区、命名约定——会演化，但增补必须"改数据不改逻辑"；能用特征/测量替代的就不用枚举（轮廓节让异常目录自己浮出；venv 用前缀而非精确名）。增补只在新病例出现时进行，不预防性添加。
3. **仓库自声明层**：仓库根的 `.repo-hygiene.json` 声明仓库自己的特异性——`process_areas`（过程区位置）、`extra_prune`（额外剪枝目录）、`skip_checks`（不适用的检测项编号）。仓库特异性知识留在仓库里随其演化，脚本不去追所有仓库的约定。仓库已有自声明（如 docs map 类文件）时优先读取而非另造一套。

语义判断（轮廓异常的意义、信号是否成立、如何处置）永远归 agent 与用户——脚本不假装全能。

## 工作流

1. 运行 `scripts/repo-hygiene.py <repo_root>`（默认当前目录），获取机械信号。先看报告第 0 节**仓库轮廓**（体量 top 目录）：轮廓不依赖任何预设检测项，体量大或陌生的目录会自己浮出来。仓库的过程产物区不在默认候选（docs/temp、`.zcode/plans` 等）时，用 `--areas=路径1,路径2` 显式指定，或写入仓库自声明。
2. 逐类核实：对每类信号抽查 2-3 个样本确认成立（读文件 / git 历史），剔除误报；**同时环顾轮廓节**——异常体量目录背后是否有检测项未覆盖的失序（检测项未命中 ≠ 无问题）。
3. 按「检测项与判定标准」给出分级处置建议，交用户确认。
4. 用户确认后执行清理；删除文件时同步清理其引用（入口注册、文档交叉引用、索引行）。
5. 收尾报告：扫了什么、确认几类信号、清了什么、留了什么及理由——不做逐条流水账。

## 检测项与判定标准

| # | 信号 | 判定成立的依据 | 典型处置 |
|---|---|---|---|
| 1 | gitignore 反向漏：文件被 git 追踪但命中 ignore 规则 | 脚本直接给出（`git ls-files` ∩ check-ignore） | `git rm --cached` + 提交；ignore 规则的本意是"别追踪"，就必须落到实处 |
| 2 | 化石 ignore 条目：规则指向的路径已不存在 | 抽查确认路径确实消失（而非暂未生成的构建产物） | 删除该条目；路径还会再生的保留并说明 |
| 3 | 重复/冗余 ignore 条目 | 规范化后等价重复 | 去重 |
| 4 | 空壳目录：只含 .DS_Store/.gitkeep 或为空 | 确认无隐藏用途（被脚本引用 / 占位约定） | 删除；属客户端 init 残留的，同时确认对应配置无引用。**Unity 项目：删除目录必须同步删除同名 `.meta` 文件**，否则工程报 missing reference |
| 5 | 无入口脚本：不被任何 package.json / CI / 文档引用的脚本 | 抽查 grep 确认全仓无引用（含文档提及） | 一次性/探索性的删除；有复用价值的补入口，或转入合适 skill 的 `scripts/` |
| 6 | 悬空引用：$schema / 配置指向不存在的文件 | 脚本解析直接确认 | 补实际文件，或删除悬空字段 |
| 7 | 过程产物堆积：plan/temp 区文件数、超龄比例、同主题聚类 | 对照下方「过程产物生命周期」判定 | 有复用价值的沉淀（spec / memory）后删原件；无价值的删除 |

## 过程产物生命周期（temp/plan 判定基准）

过程产物（执行计划、plan、子任务稿）三态：

- **wip**：任务进行中，允许存在。
- **done → 收口**：任务完成时，有复用价值的结论沉淀进 spec 或 memory，**随后删除原件**。收口的唯一定义是"沉淀完成 + 原件删除"——只把 TODO 全勾选不算收口。
- **直接删除**：无复用价值的（纯执行记录、已被取代的方案稿），任务结束即删。

巡检判定：完成超过 14 天未收口的、无状态信息的、同主题 3 份以上的，列为失序信号。同主题多份计划反复出现，同时意味着该架构债在被反复局部重攻——除清理外，应提示用户该主题需要 problem-triage 式根因裁定。

## 边界外发现的收口

核实与环顾中发现脚本边界外的情况时，按性质三选一，不混用：

1. **可特征化的通用模式**（如新生态的标准产物目录、通用命名约定）→ 增补脚本的枚举/特征表——病例驱动、改数据不改逻辑。
2. **仓库特异性**（如本项目的过程区在 `output/`）→ 建议用户写入仓库根的 `.repo-hygiene.json`：一次声明、长期生效、随仓库演化。这是仓库特异性知识的正式归宿，防脚本枚举表无限膨胀。
3. **一次性语义判断**（如某目录的历史价值）→ 报告用户裁决，不沉淀到脚本。

## 已知限制

明确声明覆盖边界，避免"有巡检就高枕无忧"：

1. 只检测**机械可判**的失序；语义层腐化（重复实现的逻辑、漂移的术语、注释语义过期）检测不到——变更时由 stale-representation 按继承面处置，跨产物对照走 design-review，系统性问题定性走 problem-triage。
2. 无入口脚本、化石 ignore 条目为启发式检测，存在误报（动态加载、外部工具引用、路径暂未生成），必须经工作流第 2 步核实。
3. **生态偏向**：无入口脚本检测的引用语料覆盖 JS/TS（package.json）、Python（pyproject/setup/tox）、通用构建（Makefile/justfile/Taskfile/CI/README）；其他生态（Go/Rust/Java 的自有任务定义）覆盖弱，该检测项在这些仓库以人工核实为准，勿按输出直接清理。
4. 同主题聚类对 `xxx-global-plan / xxx-sub-plan-N` 命名约定最敏感；其他命名习惯下退化为 `-plan` 后缀匹配，聚类覆盖会弱——聚类为空不代表无重攻，只代表机械信号未命中。
3. 巡检是周期快照，不替代任务级收尾（sweep）与交付自检（delivery-check）——它兜的是"每次都漏一点"的累积账。
4. 检测项本身刻意从真实病例归纳（v1 只收录验证过的失效模式），而非想象中的通用清单；新仓库跑出新的失效模式时，经病例确认后再增补检测项，防巡检项自身膨胀。

## 禁止事项

- 禁止按脚本输出未经核实直接删除。
- 禁止把巡检报告落盘成仓库新文档（防自我繁殖）。
- 禁止在巡检中顺手重构、顺手改代码——失序信号之外的发现，记录并转对应 skill。
- 禁止清理归属不明的文件——查来源（git 历史）后仍不明的，报告用户裁决。
