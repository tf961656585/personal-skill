# 视觉交付与人工验收（visual-handoff）

统一一类任务的处置口径：凡是"看一眼就知道"的事（版式、观感、审美、截图里有没有问题），agent 都不能用推导代替感知，也不能自己宣告通过。

理由（why）：感知是"读"，推导是"算"。读有天然的终止信号（看到了就是看到了）；推导只有不可判定的"我没再发现问题"——没有外部终止判据，agent 要么凭感觉停在假绿处，要么无限换角度，时间与 token 无上界。而"显眼 / 一眼可见"本身是只对感知体存在的属性，agent 没有它的入口，因此也评估不了"这个问题值不值得交给人看"。终止判据与通过权都必须由人从外部给定。

## 1. 三件事分界

| 类别 | 判据形态 | 谁做 | 结论强度 |
|---|---|---|---|
| 渲染检查 | 几何/数值/存在性断言：外接矩形重叠、内容溢出画布、空白页、资源缺失、图表数值与数据源一致、页码目录连续 | agent，脚本 | 硬事实，可阻断交付 |
| 缺陷预检 | 离散可命名的可见缺陷：压字、裁切、明显错位、字号过小、图片变形 | agent（含插件视觉评审子代理） | 只报「疑似缺陷清单」+ 可能漏检；非阻断、不作验收依据 |
| 视觉验收 | 整体观感、审美、视觉重心与平衡、风格调性、"是不是要的那幅画面" | **用户专属** | 唯一有权宣告「通过」 |

## 2. 不可跨越的鸿沟（这些一律列为待人工确认项）

审美与高级感；视觉重心与平衡、留白节奏；风格与调性是否符合语境；生成式图片的语义正确性（图中文字是否乱码、内容是否与主题矛盾）；真实宿主与介质下的呈现（PowerPoint 字体替换后的重排、投影距离可读性、打印效果）；跨页风格一致的主观判断。

## 3. 一眼类问题：判据、禁令、终止预算

判据：人打开产物后一次注视或一次操作即可得出结论。

- 禁止以"先自己测一测 / 写个脚本看看"作为第一步。
- 程序化指标（外接矩形、像素测量、配色统计）只能用于**定位可疑处**，不得用于判定好坏；不得由"几何检查全绿"推出"看起来没问题"。
- **预算（写死）**：同一视觉问题只提交一次验收请求；一批改动合并为一次（重点看 ≤5 处）；禁止对同一问题发起第二轮自测。被指出的问题修复后，随下一次请求提交。

## 4. 验收材料（交付或确认时必附）

- **怎么打开**：命令 / URL / 文件路径；注明真实宿主与预览渲染的差异（如 LibreOffice 预览 ≠ PowerPoint 实际字体）。
- **请重点看哪几处**：≤5 处，每处一句怀疑点——不是把 N 张渲染图原样甩出。
- **已知未验项**：程序化检查覆盖不到的部分。
- **明确请求**："视觉验收待你确认"。
- 免审出口：用户明确免审时不再请求，结论表述也不升格；无人值守时停在交接点记为待确认，不代为自审。
- 时效：用户确认后，任何后续编辑（重排、换图、改文案）作废该次验收，须重新提交。

## 5. 措辞与证据等级

禁用措辞：视觉验收通过 / 视觉检查通过 / 肉眼确认 / 看起来没问题 / 版式无问题。
替代表述：渲染检查已通过（几何/数值 N 项）/ 缺陷预检未发现明显问题（可能漏检）/ 视觉验收待你确认。

第三方与插件提供的评审角色（含官方视觉评审子代理）的输出一律按「缺陷预检」对待——不修改它们，也不采信其结论等级。

## 6. 按载体组织要点

| 载体 | agent 侧可做 | 列为待人工确认 |
|---|---|---|
| PPT / 课件 | 逐页渲染、溢出与缺图、页码与占位残留 | 观感、投影距离可读性、AI 图语义正确性 |
| 文档 / 表格 / PDF | 分页伪影、被裁列（####）、错误值、目录页码 | 整体读感、版面"够不够味" |
| 成品图 / AI 图 | 尺寸、清晰度、是否空白等像素级项 | 图中文字是否乱码、内容是否与主题矛盾 |
| 网页 / 原型 | DOM 与计算值的结构化断言（prototype-standard：主线程无视觉、禁截图） | 视觉与交互观感；首选 playwright 的用户标注模式验收（用户在活页面画框 + 评论） |
| 程序截图 | 截图本身（改完界面/功能后，截图即一次验收请求，不进入结果分析长链） | "看起来对不对"归用户 |
| 视频 | 时长、黑帧、尺寸抽帧检查 | 节奏与整体观感 |

## 7. 与相邻 skill 的衔接

- `delivery-check`：第 11 条，交付前收口自检。
- `design-guide`：UI 四段式的「用户评审」是本规范的一个实例；「怎么打开 + 重点看哪几处」为通用附则。
- `implementation-discipline`：渲染验证优先结构化读取；截图不作版式判断依据。
- `master-subagent`：图证规则——截图是材料，agent 只核可程序化项。
- `prototype-standard`：主线程无视觉、禁截图；验收归用户。

## 8. 边界（Do NOT）

- 不禁止看图——禁止的是"由看图下结论"。缺陷预检有真实价值（替人挡掉机械缺陷），但必标可能漏检、不作验收。
- 不替用户判断"这个不用看"（agent 评估不了显眼程度）；只判断"哪些需要人看"。
- 不写具体程序化检查脚本（归各载体 skill）。
- 不用测量数字反驳用户的视觉观察：用户说"看着别扭"即有效证据，先复现用户视角。
