# 项目入口与文档地图（project-entry）

## 入口顺序

- 进入具体项目后，先读项目根 `AGENTS.md`（仓库级轻入口），理解仓库级规则与阅读原则。
- 详细任务路由、文档分发关系与定义优先级，按需读取 `docs/agent-map.yaml`；它是按需加载材料，不得形成第二套 spec 定义。
- 进入实现前，必须已读取与任务相关的 primary spec 基准。相关 spec 的发现顺序（每层缺失自动下落一层）：
  1. `docs/agent-map.yaml` 的 `routes`（有则按任务模式匹配必读清单）；
  2. `python3 "$HOME/.agents/skills/spec-guide/scripts/design_lint.py" --list-artifacts docs --root .`（派生索引，一次看全产物与状态）；
  3. 约定目录结构（`docs/spec/`、`docs/adr/` 等）；
  4. **按改动区域反查**：用本轮将要改动的文件路径、符号名、模块名、术语去 `docs/` 检索——任务描述里的词常常不是设计文档用的词，改动区域才是可靠锚点；
  5. 全文检索（任务描述中的关键词）。

- **设计基准检查与回执（硬约束）**：进入实现前，必须以本轮实际的文件读取或检索为证据，确认与任务相关的主 spec 基准（只在回复里写「已检查」而本轮没有对应读取/检索，不算完成）。检查结果只在会影响结论时对外披露：在首条实质回复的结论之后用业务语言补一行依据，路径与章节放「技术备注」。
  - 命中且影响结论：`依据：设计文档里定的「<业务主题>」方案`；技术备注写 `<spec/设计文档路径> §<节>`
  - 未命中：不影响结论时不播报；用户问起或结论依赖「没有现成基准」这一事实时，写 `依据：没找到相关设计基准（查过：<业务名 / 模块名>）`
  - 仓库无设计层产物：默认不播报；需要交代时写 `依据：仓库里没有设计文档`

  同一会话内开始新的实现任务（用户追加范围或换模块）时重新检查；设计层的规划任务同样需要检查，因为它决定后续实现继承哪份基准。用户要求审计时，完整列出检查过的路径与检索词。

## memory/ 读协议

仓库根存在 `memory/` 目录时，它是经验性记忆库（可探索、非必读；用前须按条目的失效条件核验仍成立）。DSH 里由记忆插件负责读写并提供工具；其他客户端、或插件不可用时，按文件降级读取。

以下时刻必须先召回：

- 进入仓库开工
- 开始排查异常/报错
- 改动不熟悉的模块前（可观测化口径：本会话第一次编辑某个未读过的文件前）
- 做技术决策/取舍前
- 用户提及"之前/以前"的经历时

### 优先：记忆插件工具

以本轮实际调用 `memory_recall` 为召回证据（查询用文件路径、符号、命令、报错串、模块名、用户措辞）。命中后用 `memory_get` 读全文，再按失效条件核验。

- 自动召回（`〔记忆召回〕`）只是线索，同样要按失效条件核验。
- **召回检查与回执（硬约束）**：在上述触发时刻，必须有本轮的 `memory_recall` 调用（或插件不可用时的 `MEMORY.md` 读取）；只在回复里写「已检查」不算完成。同一会话内未改动 `memory/`、也未运行 `/reflect` 时可复用上次结果并注明复用。检查结果只在命中且会改变结论时披露：在结论之后用业务语言补一行依据，引用命中的钩子与 `file#id`；引用里保留内部标识符时先给一句业务含义。
  - 命中且影响结论：`依据：之前记过「<钩子> → file#id」`
  - 未命中：不播报
  - 仓库无 `memory/`：不播报
  - 未认证 / 未识别布局：只在用户问起依据或需要说明可靠性时写一行 `依据：记忆格式未认证，未作为依据`
- 扫到"待确认提案"非空时，主动提醒用户有提案待拍板；裁决前不自行落盘必读层改动。裁决后由落盘方删除提案并移除索引。
- **消费前核验是硬约束**：深入读取任意一条记忆、准备据此行动前，必须当轮重新确认失效条件未触发——读代码或核实现状，证实"what 与 why"仍然成立。记忆的自动失效识别只机械覆盖"证据文件消失"一种模式；语义/行为变化型失效（最常见）不会被自动检测。因此"记忆已存在"不等于"记忆仍有效"，每次消费都必须独立核验。
- 核验后发现失效：不以该记忆为依据行动；用 `memory_stale` action=mark 记下失效证据，不要直接修改或删除条目——删除由完整反思（`/reflect`）处理。
- 记忆与代码 / spec 冲突时以代码和 spec 为准。
- 不得直接编辑 `memory/` 文件；写入、删除、索引重建归记忆插件。仓库根不存在 `memory/` 属正常状态，不视为缺失，禁止主动创建——初始化由记忆插件的首次写入完成。

### 降级：插件不可用时按文件读

1. **先看格式标记**：读 `MEMORY.md` 顶部的 `<!-- memory-schema: N -->`。缺标记或版本低于当前格式：按现有文件内容尽力读取，旧索引行当摘要读（相关性弱），对外披露依据时标注未认证；不要按新语义猜测旧行。版本高于当前格式：只读，不据此写入。`MEMORY.md` 不存在但 `memory/` 存在：标注未识别布局，不读索引、不猜测。
2. 索引行是**触发钩子**，不是内容摘要：它只回答"下次什么情境下该读这条"，结论在主题文件条目里。判断相关性时，拿当前任务手里的表面信号（文件路径、符号、命令、报错串、模块名、用户措辞）去匹配钩子，不靠语义联想；匹配不上就明确跳过。索引是生成物，读侧只读，不要改写。
3. 命中后按索引行的 `file#id` 定位条目：在主题文件里 grep `- id: <id>` 拿到行号，再读上方最近的 `## ` 标题到下一个 `## ` 之间，不整文件读。
4. `memory/stale.md` 与 `memory/inbox.md` 是工作队列，不是可检索记忆；读协议不消费它们，也不把它们当事实来源。
5. 发现失效：按下面格式追加到 `memory/stale.md`，不直接修改或删除条目；删除由完整反思执行。`stale.md` 不存在时创建（标题 + `（无）` 占位）；只有占位时先清掉占位再追加。

待清理队列格式（一行一条；`file#id` 定位条目，`—` 后写失效证据；行首日期是**发现失效的当天**，不是条目捕获日）：

```markdown
- <YYYY-MM-DD> <主题文件>#<id> — <失效证据：读到的现状 / 与记忆矛盾之处>
```

手工追加时严格按上面的格式；解析不了的行（包括漏写行首 `-`、以日期开头的行）会阻断下次认证。

## 边界（Do NOT）

- 不写入、不删除记忆条目（归记忆插件）；发现失效只标记或追加待清理队列并报告，删除与索引重建由完整反思执行。
- 不伪造设计基准或记忆依据：仓库没有设计层产物、没有命中条目时如实说明，不为凑格式编造路径、章节或索引行。
- 不在无触发时刻的每一轮都扫索引；回执只在触发时刻完成，且只在结论会被影响时对外披露。
- 不重复「基本判断链」骨架与 spec 体系路由（design-guide / spec-guide）。
