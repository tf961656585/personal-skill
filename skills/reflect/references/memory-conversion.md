# 记忆导入：把任意来源转换成 reflect 记忆格式

## 定位

本文件是 reflect 导入模式的作业指导书，也是“其他格式的记忆如何转换”的唯一权威说明。它回答**怎么转换**，不重新定义目标格式——索引行、条目字段、队列语法的单一来源是 `reflect-memory.py schema` 的输出；`SKILL.md` 的「记忆条目格式」「存储布局」只给示例。

触发：用户说“把 X 的记忆导进来”，或调用 `/reflect --import <path>`。仅手动触发，不自动扫描磁盘或所有仓库。

导入不是“把旧文件改写成新字段”，而是按目标记忆的准入标准重新提炼。源里通常只有结论，没有“下次什么情境下读”和“什么变化后失效”；这两项推不出来时，正确动作是进待补队列，不是编一个看起来合理的值。

## 源的范围

可以导入的是**记忆类产物**：

- 本仓库或其他项目的 `memory/` 目录；
- 其他 agent / 客户端的记忆目录（只读，不改源）；
- docs 里的经验记录、决策记录、踩坑清单；
- 用户指定的单篇笔记或一组笔记。

不是记忆、不导入的：

- 原始对话记录、会话日志——属于日志；要沉淀走正常 reflect 的提炼流程，不走导入；
- 任务状态、待办、临时笔记、构建产物；
- 纯代码注释、README 说明——属于代码/文档，不是经验记忆。

源文件只读：导入不修改、不删除源；来源路径与行号写进条目的证据字段。外来记忆系统不迁移、不改写，只读取并写入目标 `memory/`。

## 转换管线

0. **发现与边界**：确认源路径；若是目录，先找源自己的索引或目录结构；列出将读取的文件；确认没有越界文件。
1. **抽取候选**：按源的天然单位切分（一个标题 / 一条 bullet / 一个文件）；保留来源位置。
2. **准入与路由**：判断候选是否属于六类可复用信号之一；属于稳定规则/契约的走必读层提案；属于日志/任务状态/一次性的丢弃。
3. **字段映射**：按下方映射表填目标字段，推不出的不伪造。
4. **证据核验**：回读代码 / spec / 原文，确认 claim 仍成立；证不了则进 inbox（缺证据）。
5. **去重合并**：与目标已有条目比对；同主题按合并规则处理，不建平行条目。
6. **残缺处理**：缺必填字段的条目写入 `memory/inbox.md`，不进入主题文件与索引。
7. **写入**：合规条目写入主题文件，并生成稳定 `id`；索引不手写——运行 `reflect-memory.py index`（或最后 `certify`）从条目字段渲染「条目」区块。
8. **校验与认证**：运行 `reflect-memory.py check`；无阻断信号后运行 `certify` 写合规标记。认证失败则修到通过，不手写标记。
9. **报告**：按 imported / merged / skipped / needs-decision 四类逐条报告，说明来源、去向与原因。

## 准入与路由

| 候选性质 | 去向 |
|---|---|
| 可复用的踩坑 / 隐藏依赖 / 情境事实 | 主题文件 + 索引 |
| 已拍板的决策及原因 | `decisions.md` + 索引 |
| 被用户纠正的偏好 | `preferences.md`；通用稳定则走必读层提案 |
| 稳定规则 / 契约 / 流程 | 必读层提案（不写成记忆） |
| 日志、任务状态、临时上下文 | 丢弃 |
| 可复用脚本 | 既有 skill 的 `scripts/` 或新建 skill 提案 |

## 字段映射

| 目标字段 | 从源里找什么 | 推不出时 |
|---|---|---|
| id | 从条目标题派生短 ASCII slug；同文件内唯一 | 必填；导入时必须生成，不能留空 |
| 类型 | 六类信号归类 | 归入最接近的一类；归不进则 inbox |
| 作用域 | 通用经验 → user；仅本仓库 → project | 默认 project |
| 钩子 | 源里“什么情境下会想起它”的短句；不能含 `→` | 可由触发压缩；推不出就缺省（索引回退用触发） |
| 触发 | 源里“当时在做什么 / 看到什么现象”的线索 | inbox（缺触发） |
| 证据 | 文件:行 / 对话依据 / 原文档位置 + 来源路径 | inbox（缺证据） |
| 捕获于 | 本次导入日期 | 必填，取当天 |
| 失效条件 | 什么变化会让它不再成立 | inbox（缺失效条件） |
| 内容 | 可复用的 what + why；丢掉叙事过程 | 只剩流水账则丢弃 |

**触发与失效条件是一对**：触发是读的守卫（什么时候该打开），失效条件是信的守卫（什么时候不再可信）。两者推不出时，不伪造，进 inbox。

**字段行必须从第 0 列开始**：缩进行被视为「内容」续行，不参与字段解析；因此多行内容可以安全包含 `- 类型: ...` 这类项目符号。字段行本身半角/全角冒号都接受。

`id` 是索引锚点，不是标题的复制：同文件同日多条也能精确指向其中一条。缺 `id` 的条目同样进 inbox，补齐后才能进入主题文件与索引。主题文件名必须是 `memory/` 下的单段名称，不能含空白、路径分隔符、`#`、`→`，否则索引行无法解析。

导入时 `scope: user` 默认降级为 project；确属通用、值得全局生效的候选，合成**一份**必读层提案，不生成 N 份。

## inbox 队列

`memory/inbox.md` 是导入时的待补工作队列，不是可检索记忆，也不是归档区。

格式（一行一条）：

```
- [待补] <来源路径>:<行> | 缺: <字段列表> | <条目标题> — <一句话内容>
```

生命周期：

- 导入时，缺必填字段的条目写入 inbox；
- `/reflect` 逐条处理：能补齐并核验 → 移入主题文件 + 登记索引；已过时 → 带证据删除；仍补不齐 → 保留并报告；
- `check` 把 inbox 非空报为信号；
- 合规标记不因 inbox 非空而阻断——标记认证的是活动索引，不是待补队列。

## 就地改写与备份

- 默认就地改写，但必须先备份：有 git 用 git 提交/快照；没有 git 则整目录复制为带时间戳的备份。
- 两者都不可用、或源目录有未跟踪的未知文件 → 中止并报告，不改写。
- 先写主题文件与队列，最后写索引；`certify` 最后写标记。标记是提交点：中途失败，下次仍按未认证状态续跑。新建骨架（`init`）不含标记，标记只由 `certify` 写入。
- 迁移必须幂等：重复运行不产生重复条目、重复索引行或重复队列行。

## v2 → v3 迁移

1. 给每条条目加 `- id: <短 ASCII slug>`，同文件内唯一；标题和日期不改。
2. 索引行改为 `→ file#id`；同一文件同日多条靠 id 区分，不要改日期或拆文件来消歧。
3. `stale.md` 的 `file :: 标题` 行改为 `file#id`；旧格式仍可读，但新写入用 id。
4. 运行 `check`：应无缺 id、无锚点问题；再运行 `certify` 把标记从 2 升到 3。
5. `check` 的「索引漂移」仍按日期 + 文件粗查；条目级正确性由锚点校验负责，两者都要过。
6. 索引是生成物：迁移时不要逐行改索引，给条目补好 `id`（和可选的 `钩子`）后运行 `index` 重建；`check` 会报「索引与条目不一致」。
7. `stale.md` 行首日期是读侧发现失效的日期，不是条目捕获日；定位靠 `file#id`。
8. 条目字段必须从第 0 列开始（缩进行视为内容续行）；标题分隔符可用 `—` / `–` / `-`；主题文件名不能含空白、路径分隔符、`#`、`→`。`check` 会点名不符合的条目与文件。

## 校验与认证

- `check`：格式、证据、索引与条目一致性、锚点、残余行（索引区块和队列里无法解析的行）、缺字段 / 字段重复 / 钩子保留字符、疑似条目但无法解析的标题、非法主题文件名、队列信号。只读，不改文件。
- `certify`：先校验条目形状，通过后重建「条目」区块，再做锚点 / 证据 / 队列校验，最后写 `<!-- memory-schema: 3 -->`。阻断项：缺 `MEMORY.md`、标记无法识别或高于当前版本、条目缺必填字段、字段重复、钩子含 `→`、疑似条目但无法解析的标题、主题文件名含空白 / 路径分隔符 / `#` / `→`、索引区块内有无法解析的行、索引漂移、索引与条目不一致、索引指向不存在文件、证据文件消失、锚点缺失 / 悬空 / 重复 / 日期或类型不匹配、队列文件有无法解析的行。
- 队列**非空**不阻断认证；队列里出现**无法解析的行**会阻断——那意味着读侧的失效上报可能已被静默丢弃。
- 标记只证明形状合规，不证明内容正确；内容正确性仍由读侧“消费前核验”保证。
- 禁止手写标记绕过 `certify`。

## 批量与报告

- 单批 20–30 条；超过则分批，逐批校验、逐批报告。
- 报告模板：

```
导入：<源路径>
批次：<n>/<total>
imported: <数量>（写入 <file>）
merged: <数量>（合并到既有条目）
skipped: <数量>（原因：日志 / 一次性 / 无可复用洞察）
needs-decision / inbox: <数量>（缺字段、证据不明、作用域待定）
校验：check <通过 / 阻断项>
认证：<已写标记 / 未写，原因>
```

## 非目标

- 不自动扫描整个磁盘或所有项目；范围由用户指定。
- 不为每个源写定制适配器；通用发现/抽取流程优先，同一源出现两次以上再考虑补源笔记。
- 不迁移、不改写外来记忆系统；只读取并写入目标 `memory/`。
- 不把日志当记忆导入；要沉淀先走正常 reflect 提炼。
- 不在读路径上改写源或项目 `AGENTS.md`；冲突走必读层提案。

## 安全红线

- 不伪造触发、证据、失效条件。
- 不写无锚点的索引行；锚点缺失、悬空、重复都会阻断认证。
- 不手写「条目」索引区块——它由 `index` / `certify` 从条目生成。
- 不在 `stale.md` / `inbox.md` 里写自然语言或自创格式；优先用 `stale-add` / `inbox-add` 写入。
- 不无证据删除源或目标条目。
- 不把不确定条目塞进主题文件；进 inbox。
- 不在认证失败时手写标记。
- 不在没有备份时就地改写。
