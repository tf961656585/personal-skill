# Sweep — 任务收尾扫描

## 定位

对应交付门禁（delivery-check）第 3 条（收尾扫描）。本轮编辑和新建的文件会持久留在仓库，成为后续上下文窗口的事实来源——未来的 agent 默认仓库内容可信，没有能力分辨其中对错。

"任务是否完成"只有与用户对话的人知道，因此本 skill 由用户显式调用触发，不在每轮对话后自动执行。使用习惯：**每完成一个任务，调用一次 /sweep**。

## 执行流程

1. 盘点本轮产物
   - `git status --porcelain` 与 `git diff --stat` 确认本轮修改、新建、未跟踪的文件。
   - 回顾本轮对话中实际创建过的临时产物（一次性脚本、日志、调试输出、截图、草稿）。
2. 按类别扫描残留
   - 临时脚本与调试产物：一次性验证脚本、日志文件、临时数据、调试截图。
   - 废弃草稿与被推翻的方案：旧设计稿、旧实现文件、平行版本。
   - 描述旧行为的注释 / 文档 / 测试名：行为已变但文字没跟上。
   - 与本轮结论矛盾的旧口径：文档、配置、注册入口、交叉引用里的旧说法。若矛盾对象是 spec（spec 文档或 spec 级口径），不在 sweep 内直接改 spec，转 spec-guide 场景 C 收口——sweep 只处理非 spec 的残留清理。
3. 处置
   - 命中即当轮删除或修正，禁止"以后清理""暂时保留"。
   - 删除文件时同步清理其引用（配置、入口注册、文档交叉引用、导航 map）。
4. 边界
   - 扫描范围以本轮触碰和取代的产物为界，不扩大为全仓库清理。
   - 遇到非本轮产生、归属不明的可疑文件，先查来源（git 历史、文件内容），仍不确定则报告用户裁决，不擅自删除。
5. 收尾报告
   - 一句话对齐：扫了什么、删了什么、留了什么及理由；不做逐条流水账。
